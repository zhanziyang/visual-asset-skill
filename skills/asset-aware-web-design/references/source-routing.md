# Asset source routing

Use this reference after choosing semantic type, medium, style, and placement. It helps locate suitable candidates without turning one provider into the default answer.

Provider names below are examples of source classes, not blanket endorsements or permanent license claims. Recheck current availability, format, price, attribution, trademark, model, and usage terms for the selected item before production use.

## 1. Route by need, not habit

After the visual decision, follow the matching branch:

```text
sourced asset
→ existing project / user library / official source
→ specialist source / stock / archive / open library

original non-factual asset
→ commissioned or AI-generated candidate when permitted

structural, interactive, data-driven, or generative visual
→ code-rendered HTML / SVG / Canvas / WebGL

none clearly beats typography, UI, or whitespace
→ NONE
```

The first available result does not automatically win. For a material visual, compare candidates from more than one credible source class when practical.

## 2. Product UI and physical products

| Need | Best source route | Notes |
|---|---|---|
| Real software interface | Repository, design files, staging/production capture, user-provided recording | Never substitute another product or generated dashboard |
| Mobile/device presentation | Actual UI plus official device resources or a code-rendered frame | The frame is presentation, not evidence |
| Real hardware or packaging | Manufacturer/brand media kit, owned photography, approved CAD/3D files | Preserve exact form, labeling, and proportions |
| Configurable physical object | Official CAD/GLB/GLTF, commissioned model, approved product render | Use interactive 3D only when changing view/state helps |

## 3. Brand assets and platform marks

Use the brand owner's press kit, brand portal, developer documentation, official package, or user-provided files. Repository packages may contain official marks, but verify that their use matches the brand's guidance.

Aggregators such as Simple Icons can help discover common brand SVGs, but they do not replace current trademark and usage guidance. Do not recolor, redraw, approximate, or generate a real mark outside permitted rules.

## 4. Iconography source router

Choose a complete family by style and role before downloading individual glyphs.

| Required language | Candidate sources | Fit notes |
|---|---|---|
| Neutral outline utility | Existing design system, Lucide, Heroicons outline, Tabler Icons, Radix Icons | Good for dense UI and developer-oriented products; compare stroke, corners, and optical size |
| Flexible weights and fills | Phosphor, Material Symbols, Font Awesome | Useful when states require regular, bold, fill, or duotone variants; keep one weight logic |
| Platform-native symbols | SF Symbols for Apple-platform contexts, Material Symbols for Material contexts | Follow platform and distribution restrictions; do not use as generic brand marks |
| Colorful or illustrative 2D icons | Streamline, Icons8, IconScout, DrawKit, Noun Project collections | Select one named family with full concept coverage; verify attribution and commercial terms |
| 3D icon system | Streamline 3D, Icons8 3D styles, IconScout 3D, Spline libraries | Use at large display sizes; inspect material, lighting, camera, and background consistency |
| Animated icons | Rive libraries, LottieFiles, Lordicon, Icons8 animated icons | Check runtime, editability, loop quality, license, and reduced-motion fallback |
| Official integration mark | First-party brand portal or official developer assets | Never replace with a generic utility icon |

Do not mix glyphs from different families merely to fill coverage gaps. If one family lacks a critical symbol, choose another complete family, draw a small compatible extension under the library's license, or simplify the concept set.

## 5. Photography and stock

Choose the source class from the required photographic genre:

| Need | Candidate source class and examples | Fit notes |
|---|---|---|
| Product- or brand-specific truth | Owned shoot, commissioned photographer, official first-party library | Highest specificity and production confidence |
| Distinctive contemporary editorial/lifestyle | Stocksy, Getty Images, Adobe Stock Premium, Offset/Shutterstock | Better collection curation may reduce generic-stock appearance; requires item-level licensing |
| Broad commercial selection | Adobe Stock, Shutterstock, Getty Images, iStock | Strong coverage across photos, video, vectors, and editorial; narrow by visual grammar |
| Fast placeholder exploration | Unsplash, Pexels, broad image search | Useful for composition testing, not an automatic final source |
| Historical or cultural material | Wikimedia Commons, Europeana, Library of Congress, national libraries, museum and railway archives, Internet Archive | Check the rights statement on each item; collection access does not mean every item is public domain |
| Scientific, geographic, or institutional imagery | Government open-data portals, universities, observatories, space agencies, official institutions | Confirm attribution, jurisdiction, and modification rules |

Search with photographic language, not only subject nouns: documentary, editorial, still-life, candid, studio, archival, aerial, macro, wide environmental, low-key, hard flash, natural overcast, negative space left/right, and intended aspect ratio.

## 6. Illustration and collage

Source order:

```text
existing brand illustration system
→ commissioned illustrator or user-owned library
→ a coherent licensed collection
→ public-domain print/archival material for collage
→ AI generation for non-factual original concepts
→ code-drawn illustration only when its runtime properties add value
```

Candidate libraries include Streamline illustrations, DrawKit, Blush, Storyset, Icons8 Ouch, and IconScout illustration collections. Treat these as starting points; many recognizable collections can make unrelated products look identical. Prefer a full family that matches the visual grammar and covers the required scene set.

For collage, track every source fragment. Public-domain status for one scan does not automatically cover embedded logos, artworks, people, or later reproductions.

## 7. 3D models, materials, and HDRIs

| Need | Candidate sources | Fit notes |
|---|---|---|
| Accurate real product | Manufacturer, user CAD, commissioned 3D artist | Best for factual form and configurable interaction |
| General models | Sketchfab, CGTrader, TurboSquid, BlenderKit | Quality and license vary per item; inspect topology, textures, rigging, and Web export rights |
| Open models, HDRIs, textures | Poly Haven, ambientCG | Useful for production when the selected asset's current license is compatible and recorded |
| Web-native spatial composition | Spline library or commissioned Spline scene | Confirm export/runtime terms and mobile performance |
| Scanned cultural objects | Museum open collections and institution-provided models | Preserve attribution and factual context |

Treat a 3D scene as a bundle of rights and performance costs: model, mesh, textures, materials, fonts, HDRI, animation, audio, and any embedded brands may have different origins.

Before integration, inspect polygon count, texture resolution, compression, material compatibility, animation clips, camera, lighting, and GLB/GLTF export. Create a poster or pre-rendered fallback when WebGL is unnecessary or unsupported.

## 8. Video, motion, and audio

| Need | Candidate sources | Fit notes |
|---|---|---|
| Actual product behavior | Direct screen recording or user-owned demo | Preserve real UI and state |
| Premium narrative footage | Filmsupply, Artgrid, Getty Images, Adobe Stock, Pond5 | Match camera, grade, frame rate, and release requirements across the set |
| Placeholder environmental footage | Pexels Video, broad stock previews | Mark as placeholder until cleared |
| Motion graphics and stateful animation | Rive, LottieFiles, commissioned motion, code-rendered SVG/Canvas | Prefer editable/runtime formats when state or responsiveness matters |
| Music, ambience, SFX | User-owned audio, commissioned audio, licensed stock libraries, Freesound for item-specific open-license candidates | Verify music, voice, performance, and embedded rights separately |

Do not treat a stock loop as a premium effect by itself. Color grade, camera movement, edit rhythm, poster frame, and page motion must form one system.

## 9. Diagrams, maps, charts, and code-native visuals

These usually begin with real content or data rather than an asset marketplace.

| Need | Source or implementation route | Notes |
|---|---|---|
| Workflow or architecture | Product/domain information plus HTML/SVG; optional layout libraries | Keep text accessible and structure editable |
| Quantitative chart | Real dataset plus an existing project chart system, D3, ECharts, or equivalent | Do not invent factual values |
| Geographic map | Official open data, OpenStreetMap ecosystem, Natural Earth, MapLibre/Mapbox/MapTiler as appropriate | Track data, tile, style, and attribution terms separately |
| Procedural brand field | Project code using Canvas, WebGL, shader, or CSS | Use only when generative behavior belongs to the concept |
| Simple custom icon or geometry | Existing component system or a small authored SVG | Match the chosen icon/visual grammar and expose accessible meaning |

Code-generated output should use `source.type: code_generated` and record the data source or design logic when material. A code visual is not evidence unless its underlying content is authentic.

## 10. Textures, type, and supporting assets

| Need | Candidate sources | Fit notes |
|---|---|---|
| PBR texture/HDRI | Poly Haven, ambientCG, Adobe Substance 3D Assets, approved project library | Check resolution, channels, color space, and license |
| Paper, grain, print texture | Owned scans, public-domain archives, licensed texture libraries, procedural generation | Keep subordinate and test compression/banding |
| Open Web font | Existing brand files, Google Fonts, Fontshare, official open-source repository | Verify language coverage, weights, variable axes, and redistribution |
| Commercial type | Foundry, Adobe Fonts, Monotype or other licensed service | Confirm Web embedding, domains, pageviews, and redistribution |

Do not commit a locally installed font, texture, or model merely because it is technically accessible.

## 11. Compare sources before selecting an item

For each material candidate, score:

- semantic correctness;
- visual-grammar fit;
- complete-set coverage;
- uniqueness versus generic familiarity;
- available formats and editability;
- crop or spatial flexibility;
- responsive and performance implications;
- source mode and item-level license;
- price, attribution, and operational constraints;
- expected longevity and maintainability.

Prefer one coherent collection over unrelated individually attractive assets. A provider with fewer but consistent candidates may be stronger than a marketplace with a larger catalog.

## 12. Search and stopping rules

Build queries from the preparation brief, visual grammar, composition, and responsive need. For material decisions:

1. inspect existing/owned and official sources first;
2. search at least two credible source classes or explain why one is authoritative;
3. visually inspect a curated set in page context;
4. compare with generation, code rendering, and `NONE` when those are semantically valid;
5. stop when a candidate clearly wins or when further search is unlikely to beat `NONE`.

Do not search every provider. Breadth is useful only when it changes the decision.
